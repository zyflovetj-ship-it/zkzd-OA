全流程图06 / 20
① 发起 · 员工按表单引擎生成的动态表单起草，附件与单据绑定，提交即触发流程实例。

分层分离
Router 只做参数与依赖、Service 管事务与业务、Repository 用 selectinload 防 N+1；引擎为零依赖纯函数，可脱离框架单测。
双存储适配
开发用 SQLite 零配置，生产切 PostgreSQL 16；模型变更由 Alembic 迁移，SQLite/PG 双环境已验证通过。
安全基线
访问令牌 15 min + 刷新令牌服务端可吊销；密码用 PBKDF2-HMAC 哈希（零原生依赖）；审计中间件零侵入留痕。
zk-OA 采用 五层同构架构：前端 → 接入 → 服务 → 引擎 → 数据/设施，以纯函数引擎 + 双存储适配实现轻量但对标。 5 Layers纯函数引擎双存储

PART 03 · 差异化优势

zk-OA vs 主流 OA · 差异化优势一览

优势对比16 / 20
对比维度主流 OA 商业套件zk-OA 自研落地差异结论
部署与数据主权SaaS 为主，私有化需单独授权与报价单机 Docker Compose 起步，数据全留内网，无外部依赖优势
许可与授权成本按用户数 / 并发授权，年费持续支出自研，无按人头许可费，成本 = 人力 + 硬件优势
流程引擎可塑性成熟但受产品边界约束，深度改造需二次开发自研 workflow_engine.py 纯函数图遍历，节点类型与动作可扩优势
表单与低代码建模低代码表单平台成熟，配置与学习成本高自研建模引擎：动态实体 + 记录 CRUD，零 DDL，11 种字段类型接近
业务贴合度通用能力，需大量配置适配行业场景内置报销 / 公文 / 考勤，可直接按电力业务规则定制优势
可审计与合规提供审计模块，追溯粒度随版本操作审计 + 节点日志 + correlation_id 全流程关联追溯优势
二次开发与迭代节奏需求走厂商排期，定制周期长、费用另计前后端同栈自持，内部团队直接改，需求到上线以天 / 周计优势
升级与版本演进大版本升级需停机与回归，历史定制可能冲突自持代码与 Alembic 迁移脚本，可按业务窗口试点上线接近
内网与信创适配信创适配视版本而定，需核对中间件兼容清单纯内网可离线运行，无外部依赖；SQLite / PostgreSQL 双选优势
开放与集成开放平台成熟，预置连接器丰富122 端点 + OpenAPI 自动文档已具备，外部连接器待建待补
移动端与 IM原生 App，企微 / 钉钉 / 飞书深度集成响应式 Web 可用；SSO 与 IM 已预留未接入待补
应用生态应用市场丰富，开箱即用无第三方生态，按需自建，避免冗余功能负担待补
硬差异 ①：数据主权 + 零许可 · 全量数据留内网，无按人头年费，三年期总持有成本显著低于商业套件。
硬差异 ②：流程与业务双贴合 · 引擎自研可改，报销 / 公文 / 考勤内置，电力业务规则可直接编码而非「配置绕行」。
待补短板（已排期） · 移动端与 IM、外部连接器、流程挖掘与 AI 审批，已纳入 P5 与三期规划。
结论：在 数据主权、许可成本、流程可塑性、业务贴合、审计深度、迭代节奏、内网适配 7 个维度具备结构性优势；建模能力、版本演进 2 项与成熟套件接近；生态、移动端、外部连接器 3 项落后，已在规划中补齐。 7 项优势2 项接近3 项待补
