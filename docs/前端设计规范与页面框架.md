# 中科智电 OA · 前端设计规范与页面框架

> 设计取向：**信息架构与交互范式参考泛微 e-cology**（顶部一级导航 + 左侧二级菜单 + 多页签工作区 + 卡片式页面），
> **视觉语言取自中科智电品牌标识**（深宝蓝 / 亮青蓝 / 深灰蓝）。

代码位置：`frontend/src/theme/`（令牌与主题）、`frontend/src/layouts/`（外壳）、`frontend/src/components/framework/`（页面框架组件库）。

## 一、品牌视觉规范

### 1.1 品牌三色（取自标识实测像素）

| 名称 | 色值 | 来源 | 用途 |
|---|---|---|---|
| 深宝蓝 | `#033b88` | 标识外环 | 品牌色压边、左侧菜单渐变、页签选中态、登录页品牌区 |
| 亮青蓝 | `#2ba7d2` | 标识闪电 | 强调色、图表主色、页签指示点、侧栏选中左侧竖条 |
| 深灰蓝 | `#223a5d` | 「中科智电」字标 | 标题文字基调 |

### 1.2 交互主色为什么不是 `#2ba7d2`

亮青蓝与白色文字的对比度只有 **2.79:1**，远低于 WCAG AA 要求的 4.5:1，用作按钮底色会让文字发虚、可读性差。

因此**交互主色取品牌青蓝的加深版本 `#0d7fb8`（primary[600]）**，对比度 **4.54:1**，既保留品牌青蓝调性又满足可访问性。
品牌青蓝 `#2ba7d2` 保留给**大面积色块、图标、图表、选中指示**这类不承载正文的场景。

### 1.3 主色阶

primary[200] #9ad3ec

`@

### 1.4 语义色与中性色

| 语义 | 色值 | 底色 |
|---|---|---|
| 成功 | `#17a673` | `#e8f7f1` |
| 警告 | `#e8a33d` | `#fdf4e7` |
| 错误 | `#e05545` | `#fdeeec` |
| 信息 | `#0d7fb8` | `#e6f4fb` |

中性色阶 `neutral[0..900]` 从 `#ffffff` 到 `#0f172a`，带冷调以贴合品牌深蓝。
页面底色统一 `#f0f3f8`（`bg.page`），容器白 `#ffffff`。

### 1.5 其它令牌

| 类别 | 取值 |
|---|---|
| 圆角 | xs 2 / sm 4 / **md 6**（控件）/ lg 8（卡片）/ xl 12（横幅、登录卡）/ pill 999 |
| 间距 | 4 的倍数：4 / 8 / 12 / **16**（内容内边距）/ 24 / 32 / 48 |
| 阴影 | 低饱和冷色投影 `rgba(16,36,64,·)`，避免脏灰 |

| 区域 | 组件 | 高度 / 宽度 |
|---|---|---|
| 顶部品牌栏 | `BrandHeader` | 56px，白底 + 品牌渐变压边，`position: sticky` |
| 多页签栏 | `WorkspaceTabs` | 40px，吸顶于品牌栏之下 |
| 左侧二级菜单 | `SideNav` | 216px（收起 64px），品牌深蓝渐变 |
| 面包屑 | `AppShell` 内置 | 36px |
| 内容区 | 页面自行填充 | 内边距 16px（移动端 8px） |

**一级导航来源**：后端 `/api/auth/menus` 下发的菜单树中 `parent_id === null` 的节点（当前 11 个一级模块 / 30 条菜单）。
**二级菜单来源**：当前一级模块的 `children`；若该模块本身是页面（工作台 / 消息中心 / 报表中心），侧栏展示其自身。

### 2.1 路径解析规则（决定页签标题、面包屑、侧栏高亮）

`menuModel.resolveNav` 按以下优先级解析，**顺序不能调换**：

1. **子树内精确匹配** `path === pathname` —— 保证 `/workflows/designer` 命中「流程设计」，
   而不会被路径更短、但在树中更靠前的 `/workflows`（流程中心）抢先命中；
2. 否则取**最长前缀**节点 —— `/workflows/instance/123` 无任何菜单精确匹配，回退到「流程中心」；
3. 若最终命中的节点不是精确路径，则查**动态标题字典**（`/workflows/instance/*` 到「流程详情」）；
4. 都不命中则回退为一级模块名，最后回退为路径本身（不抛错、不空屏）。

> 这一顺序踩过坑：早期实现是「递归时遇到前缀就返回」，导致 `/workflows/designer` 被解析成「流程中心」，
> 且 `/workflows/instance/123` 因为只做精确匹配而解析不出一级模块，侧边栏与面包屑会整个空掉。
> 现已由 `npm run test:nav` 的 25 项断言锁死（含修复前逻辑的对照）。

## 三、多页签工作区

这是泛微 e-cology 最具辨识度的交互，本项目按如下规则实现（`frontend/src/layouts/workspace.tsx`）：

| 行为 | 规则 |
|---|---|
| 打开 | 路由变化即打开对应页签并激活；重复打开同一路径只更新标题 |
| 首页 | `/`（工作台）固定不可关闭 |
| 关闭 | 关闭当前页签后自动激活其右邻（无右邻则取左邻） |
| 右键菜单 | 刷新本页 / 关闭本页 / 关闭其他页签 / 关闭全部页签 |
| 刷新 | 递增页签 `nonce` 强制重挂载该页内容（等价于泛微「刷新本页」） |
| 上限 | 同时 12 个页签，超出时从最早的可关闭页签开始淘汰（不动当前页签） |
| 保活 | 每个页签用 `useRoutes(appRouteObjects, tab.key)` 独立渲染，未激活页签以 `display:none` 隐藏而非卸载 |

**保活的代价（务必知晓）**：已打开的页签会一直挂载，其 `useQuery` 的 `refetchInterval` 在后台仍会轮询。
页签上限 12 是为了约束这一开销。若后续要彻底解决，可把隐藏页签的轮询改为「激活时才轮询」。

**页面如何改写页签标题**：使用 `useTabTitle(title)` 钩子，例如详情页把「流程详情」改成具体单号。

## 四、页面框架组件

全部从 `frontend/src/components/framework` 导入：

`@tsx
import {
  PageContainer, SectionCard, FilterBar, FilterItem, DataTable,
  StatusTag, StatCard, EmptyState,
  FormSection, FormFooterBar, DescriptionsCard, ActionBar,
} from "../components/framework";
`@

| 组件 | 作用 | 关键 props |
|---|---|---|
| `PageContainer` | 页面骨架：标题 + 说明 + 右上操作区 | `title` / `description` / `extra` |
| `SectionCard` | 带品牌色标题条的白色卡片 | `title` / `extra` / `flush`（内容去内边距，供表格铺满） |
| `FilterBar` + `FilterItem` | 列表页筛选条，回车即查询 | `onSearch` / `onReset` / `extra` / `loading` |
| `DataTable` | 表格：统一分页、空态、密度 + 工具栏 | `toolbar` / `title` / `extra` / `card` / `pagination` |
| `StatusTag` | 状态标签，内置全模块状态字典 | `status` / `map` / `fallback` |
| `StatCard` | 指标卡（左侧品牌渐变图标块） | `label` / `value` / `suffix` / `icon` / `onClick` |
| `EmptyState` | 统一空态 + 可选主操作 | `description` / `actionText` / `onAction` / `compact` |
| `FormSection` | 表单分组卡片 | `title` / `description` / `extra` |
| `FormFooterBar` | 表单底部操作条 | `hint` |
| `DescriptionsCard` | 详情页分区 | `title` / `extra` |
| `ActionBar` | 卡片内工具栏 | `extra` |

### 4.1 状态字典

`StatusTag` 内置了跨模块的状态映射（流程 `draft / running / approved / rejected`、报销 `submitted / paid`、
考勤 `normal / late / early / absent`、启用态 `active / disabled` 等）。
页面有特殊状态时传 `map` 局部覆盖，**不要**再各自硬编码 `Tag color`：

`@tsx
<StatusTag status={row.status} />
<StatusTag status={row.status} map={{ reviewing: { label: "复核中", color: "gold" } }} />
`@

## 五、三种页面范式

### 5.1 列表页（已示范：`pages/Employees.tsx`）

`@tsx
<PageContainer title="账户管理" description="维护员工账号、角色与部门归属。">
  <FilterBar onSearch={() => setKeyword(input)} onReset={reset}>
    <FilterItem label="关键字" width={240}>
      <Input value={input} onChange={(e) => setInput(e.target.value)} />
    </FilterItem>
  </FilterBar>

  <DataTable
    title="员工列表"
    rowKey="id"
    loading={q.isLoading}
    dataSource={q.data || []}
    columns={columns}
    scroll={{ x: "max-content" }}
    toolbar={
      <>
        <Button type="primary" icon={<PlusOutlined />}>新建</Button>
        <span style={{ marginLeft: "auto", color: "var(--zk-text-secondary)" }}>
          共 {q.data?.length ?? 0} 条
        </span>
      </>
    }

`@

约定：**操作列固定右侧**（`fixed: "right"`）、**单行操作按钮用 `type="link" size="small"`**、

## 六、把旧页面迁移到新框架（5 步）

1. **换页头**：把 `<h2>标题</h2>` 或 `Typography.Title` 换成 `<PageContainer title=... description=... extra=...>` 包裹整页。
2. **换筛选区**：把散落的 `Input.Search` + `Space` 换成 `FilterBar` + `FilterItem`，查询/重置按钮由组件统一提供。
3. **换表格**：把 `<Table>` 换成 `<DataTable>`，去掉页面自带的 `<Card>`，操作列加 `fixed: "right"`。
4. **换状态标签**：把 `<Tag color={...}>` 换成 `<StatusTag status={...} />`。
5. **换空态 / 加载**：把 `<Empty>` 或手写 Spin 换成 `EmptyState`；加载态交给 `DataTable` 的 `loading`。

**注意**：业务逻辑（`useQuery` / `useMutation` / 表单 / 权限判断）**不要动**，本框架只替换呈现层。

## 七、响应式与移动端

| 断点 | 行为 |
|---|---|
| > 1200px | 完整形态：顶部一级导航 + 左侧二级菜单 + 多页签 |
| 768 ~ 1200px | 顶部导航横向滚动，左侧菜单可手动收起（64px 图标态） |
| < 768px | 顶部一级导航隐藏，改由左上角汉堡按钮唤出抽屉式菜单；隐藏「协同办公平台」副标题；内容内边距 8px |

多页签在移动端**保留**（横向可滚动），因为它同时承担了「返回最近页面」的职责。

## 九、后续建议

1. **继续迁移其余 22 个业务页面**到第五节的三种范式（当前仅工作台与员工管理完成）。
   迁移时注意：`PageContainer` 会渲染页头，旧页面里自带的 `<h2>` / `Typography.Title` 要一并删掉，否则标题会重复。
2. **`public/sw.js` 目前未被注册，且其缓存策略是「缓存优先」**——一旦注册，发版后浏览器会一直返回旧 `index.html`，导致前端白屏。
   若要启用 PWA，必须先把导航请求改为 network-first，再在 `main.tsx` 中注册。
3. **首屏体积**：`echarts`（仅报表中心用）与 `@xyflow/react`（仅流程设计器用）已随路由懒加载拆出，
   但仍可进一步用动态 `import()` 把 `echarts` 推迟到图表真正渲染时加载。
4. **隐藏页签的轮询**：见第三节「保活的代价」，可按需改为激活时轮询。
5. **深色模式**：令牌已集中，后续只需在 `tokens.ts` 增加一套暗色值并切换 `ConfigProvider` 的 `algorithm`。
6. **补齐前端测试**：目前只有 `npm run test:nav` 一项（覆盖导航解析）。
   项目没有引入测试框架；若要继续加测试，建议引入 Vitest + @testing-library/react，并把 `tests/menuModel.test.mjs` 迁移为 `.test.ts`。
