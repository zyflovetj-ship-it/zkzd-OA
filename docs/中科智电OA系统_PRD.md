## 2. 项目概述

### 2.1 背景

中科智电（江苏）能源有限公司业务覆盖电力交易、AI 算法与能源管理，团队规模持续扩大。当前审批、考勤、报销、公告等信息分散在微信群、线下表格与零散系统中，存在**流程不可追溯、协作效率低、数据口径不统一**三大痛点。为替代分散的审批流程与信息孤岛，需建设统一的 OA 系统。

### 2.2 目标

- **流程线上化**：请假、报销、采购、用印、合同等审批全部在线发起与流转。
- **数据可追溯**：每笔审批、每次操作均留痕，支持审计与回溯。
- **协作高效化**：待办统一汇聚、消息实时触达、文档集中管理。

### 2.3 范围

| 类别 | 包含 | 不包含（本期） |
| --- | --- | --- |
| 功能 | 首页工作台、流程审批、人事管理、行政办公、财务管理、系统管理六大模块 | 薪酬核算、发票税务对接、BI 深度分析（列入三期规划） |
| 接入 | 企业微信/钉钉单点登录（规划）、现有财务系统对接（规划） | ERP、CRM 等外部业务系统深度集成 |
| 终端 | Web 管理端、移动端响应式适配 | 独立原生 App（后续迭代） |

### 2.4 术语表

| 术语 | 说明 |
| --- | --- |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| 工作流实例 | 一次具体审批流程的运行时记录（如「张三的请假单」） |
| 会签 | 多个审批人需**全部通过**方可进入下一节点 |
| 加签 | 当前审批人在自己之前/之后**追加**一个审批节点 |
| 转办 | 将当前待办**改派**给他人处理，原处理人留痕 |
| 撤回 | 发起人将**仍在流转中**的流程撤回至草稿 |
| 催办 | 发起人对超时待办发起提醒，生成节点日志 |
| SLA | 服务等级协议，此处指审批超时阈值（默认 3 天） |

## 3. 用户角色与权限矩阵

系统采用三档角色 + 细粒度权限码（RBAC）。权限码以 `模块:动作` 形式表达，新增能力按「查看 / 管理」两级发放。

| 角色 | 说明 | 典型权限码 |
| --- | --- | --- |
| **管理员（admin）** | 系统总负责人，拥有全部权限 | 全部（`org:*`、`wf:*`、`att:*`、`expense:*`、`doc:*`、`audit:*`、`report:view`） |
| **部门负责人（manager）** | 部门经理，可审批本部门流程、查看团队数据 | `att:view`/`att:manage`、`expense:view`/`expense:manage`、`doc:official:view`/`manage`、`wf:monitor`、`report:view` |
| **普通员工（employee）** | 公司员工，仅提交与查看自身数据 | `att:view`、`expense:view`、`doc:official:view`、`doc:view`、`msg:view`、`model:view` |

## 4. 功能需求详述

> **实现基线标记**：✅ 已落地（zk-oa 现有代码/接口已支持） ｜ 🟡 规划中（工作流引擎可配置实现，本期排期） ｜ ⬜ 待评估

### 4.1 模块一：首页工作台

**目标**：一屏聚合「待我处理 / 我已处理 / 我发起」与关键数据，作为全员每日入口。

#### FR-1.1 待办 / 已办 / 我发起

- **功能描述**：聚合当前用户的工作流任务。待办来自 `workflows/pending`；已办为已完成任务；我发起为本人创建的实例列表。
- **用户故事**：作为员工，我希望登录后直接看到「待我审批」与「我发起的流程」，以免遗漏。
- **前置条件**：用户已登录，且持有对应流程的待办/实例。
- **操作流程**：登录 → 工作台首页 → 切换「待办 / 已办 / 我发起」标签页 → 点击进入详情处理。
- **异常处理**：无待办时展示空态引导；实时事件（SSE）到达时自动刷新列表，断线时 30s 轮询兜底。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-1.2 公告通知与消息中心

- **功能描述**：顶部铃铛展示未读消息角标（请假/审批/公告自动触发），支持单条/全部已读与跳转关联页。
- **用户故事**：作为员工，我希望重要审批指派与公告发布能主动提醒我。
- **前置条件**：用户已登录。
- **操作流程**：铃铛点击 → 消息列表 → 标记已读 → 跳转业务页。
- **异常处理**：SSE 断线时保留轮询，最终一致。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-1.3 日程提醒与常用应用入口

- **功能描述**：展示近期日程（打卡提醒、审批截止）与常用应用快捷入口（请假、报销、公告、文档）。
- **用户故事**：作为员工，我希望从首页一键到达高频应用。
- **前置条件**：用户已登录。
- **操作流程**：首页 → 点击快捷入口卡片 → 跳转对应模块。
- **异常处理**：未配置日程时隐藏该区。
- **优先级**：P1 ｜ **实现基线**：✅（快捷入口）/ 🟡（日程引擎）

#### FR-1.4 数据概览卡片

- **功能描述**：展示待办数、已办数、流程平均耗时（SLA 派生）等指标卡。
- **用户故事**：作为负责人，我希望一眼看到团队流程运转健康度。
- **前置条件**：用户持有 `report:view` 或本人视图。
- **操作流程**：首页 / 报表中心 → 查看 KPI 卡。
- **异常处理**：数据为空时显示「—」。
- **优先级**：P1 ｜ **实现基线**：✅

### 4.2 模块二：流程审批

**目标**：以通用工作流引擎支撑多类审批，支持多级、会签、加签、转办、撤回、催办。

#### FR-2.1 请假申请

- **功能描述**：支持事假 / 病假 / 年假 / 调休四类，提交后自动进入审批流；关联假期余额自动扣减。
- **用户故事**：作为员工，我希望在线提交请假并实时看到审批进度与剩余假期。
- **前置条件**：员工账号、假期类型已配置。
- **操作流程**：工作台 → 请假 → 选择类型/时间/事由 → 提交 → 审批人收到待办 → 通过/驳回 → 状态回写。
- **异常处理**：余额不足时提示；审批中可撤回（退回草稿）。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-2.2 报销申请

- **功能描述**：差旅 / 办公 / 招待三类报销，草稿挂附件 → 提交触发 `expense-claim` 内置流程 → 审批通过/驳回 → 财务打款。
- **用户故事**：作为员工，我希望上传发票附件并提交报销，财务在线审批与打款。
- **前置条件**：员工账号、费用类型配置。
- **操作流程**：报销 → 新建（填明细+附件）→ 提交 → 多级审批 → 打款/撤销。
- **异常处理**：超预算预警；附件超 20MB 或类型不符拦截。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-2.3 采购申请（物品 / 服务）🟡

- **功能描述**：物品采购与服务采购两类，经工作流引擎自定义定义审批链（申请 → 部门负责人 → 行政/采购 → 财务）。
- **用户故事**：作为员工，我希望采购需求在线审批，避免线下签字。
- **前置条件**：管理员已配置采购流程定义。
- **操作流程**：工作流 → 发起「采购申请」→ 按节点逐级审批 → 归档。
- **异常处理**：节点审批人缺失时升级至兜底角色（admin）。
- **优先级**：P1 ｜ **实现基线**：🟡（引擎已支持，流程定义待配置）

#### FR-2.4 用印申请、合同审批 🟡

- **功能描述**：用印（公章/合同章）申请与合同审批，支持会签与电子签单留痕（SHA-256 哈希）。
- **用户故事**：作为行政/法务，我希望用印与合同在线审批并留痕。
- **前置条件**：流程定义已配置、签单模块可用。
- **操作流程**：发起 → 多级+会签 → 通过 → 电子签单 → 归档。
- **异常处理**：签单未完成的合同禁止归档。
- **优先级**：P1 ｜ **实现基线**：🟡（用印/合同定义待配置；电子签单✅）

#### FR-2.5 审批高级动作（多级 / 会签 / 加签 / 转办 / 撤回 / 催办）

- **功能描述**：工作流引擎支持节点级多级审批、会签（全员通过）、加签（插入节点）、转办（改派留痕）、撤回（发起人）、催办（超时提醒）。
- **用户故事**：作为审批人，我希望在复杂场景下灵活处理待办。
- **前置条件**：流程实例运行中。
- **操作流程**：待办详情 → 选择「通过/驳回/转办/加签/催办」→ 系统记录节点日志。
- **异常处理**：非审批人操作返回 403；超时实例由调度器自动升级（SLA 默认 3 天）。
- **优先级**：P0 ｜ **实现基线**：✅（引擎与动作全支持）

### 4.3 模块三：人事管理

#### FR-3.1 员工档案与组织架构 ✅

- **功能描述**：员工档案（姓名/岗位/入职日期/状态）、部门树、角色归属的集中维护。
- **用户故事**：作为 HR/管理员，我希望统一维护组织与人员信息。
- **前置条件**：管理员或 HR 权限。
- **操作流程**：系统管理 → 用户/部门 → 新建/编辑/启停/重置密码。
- **异常处理**：删除保护（admin 与有用户角色受保护）。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-3.2 入职 / 离职 / 转正 / 调岗 ✅

- **功能描述**：通过用户状态字段与部门/角色变更支持四类人事动作，操作入审计日志。
- **用户故事**：作为 HR，我希望人员变动在线记录并可追溯。
- **前置条件**：HR/管理员权限。
- **操作流程**：用户编辑 → 调整部门/角色/状态 → 保存（自动审计）。
- **异常处理**：状态非法组合校验。
- **优先级**：P1 ｜ **实现基线**：✅（状态+部门/角色变更）

#### FR-3.3 考勤管理 ✅

- **功能描述**：打卡（班次判定迟到/早退/工时）、异常申诉、月度统计、加班申请与审批、Excel 导出。
- **用户故事**：作为员工，我希望打卡并查看月度考勤；作为负责人，我希望审批异常与加班。
- **前置条件**：员工 `att:view`；负责人 `att:manage`。
- **操作流程**：考勤 → 打卡 → 月度统计；负责人 → 修正/审批/导出。
- **异常处理**：非工作时段打卡提示；导出大数据分页。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-3.4 假期余额查询与自动扣减 ✅

- **功能描述**：展示年假/调休等余额，请假审批通过后自动扣减。
- **用户故事**：作为员工，我希望随时查看剩余假期。
- **前置条件**：假期类型配置。
- **操作流程**：个人中心 → 假期余额；请假通过 → 余额自动减少。
- **异常处理**：余额不足拦截提交。
- **优先级**：P1 ｜ **实现基线**：✅（与请假模块联动）

### 4.4 模块四：行政办公

#### FR-4.1 会议室预约 / 车辆申请 / 办公用品领用 🟡

- **功能描述**：三类行政资源申请，均由工作流引擎自定义定义审批（申请 → 行政审批 → 确认）。
- **用户故事**：作为员工，我希望在线预约会议室/申请车辆/领用用品。
- **前置条件**：管理员配置对应流程定义。
- **操作流程**：行政 → 选择资源 → 提交 → 审批 → 确认。
- **异常处理**：资源冲突时提示（冲突检测二期增强）。
- **优先级**：P2 ｜ **实现基线**：🟡（引擎支持，定义待配置）

#### FR-4.2 公告发布与已读回执 ✅

- **功能描述**：发布公告，全员/指定人接收；打开即标记已读（幂等），管理员可查看阅读明细。
- **用户故事**：作为行政，我希望发布通知并知道谁已读。
- **前置条件**：`ann:manage` 发布；全员 `msg:view` 接收。
- **操作流程**：公告 → 新建/发布 → 全员收到消息 → 打开标记已读 → 管理员查看回执。
- **异常处理**：重复打开不重复计数。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-4.3 文档中心 ✅

- **功能描述**：制度文件、模板的分类管理、版本控制、鉴权下载；支持 local 磁盘与 S3 对象存储抽象切换。
- **用户故事**：作为员工，我希望集中查找制度与模板，并下载历史版本。
- **前置条件**：`doc:view` 查看；`doc:upload`/`doc:manage` 管理。
- **操作流程**：文档中心 → 上传（扩展名白名单+≤20MB）→ 分类/搜索 → 下载/版本历史。
- **异常处理**：越权下载 404；路径穿越防护（`{id}.{ext}`）。
- **优先级**：P0 ｜ **实现基线**：✅

### 4.5 模块五：财务管理

#### FR-5.1 报销单管理 ✅

- **功能描述**：报销单全生命周期（草稿→提交→审批→打款→撤销），发票作为附件登记。
- **用户故事**：作为财务，我希望在线审批并标记打款。
- **前置条件**：`expense:manage` 打款/统计。
- **操作流程**：报销 → 审批 → 打款；统计/导出（Excel）。
- **异常处理**：重复打款拦截。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-5.2 发票登记 🟡

- **功能描述**：独立发票登记与报销单关联（当前作为报销附件实现，规划独立发票台账）。
- **用户故事**：作为财务，我希望建立发票台账便于核对。
- **前置条件**：财务权限。
- **操作流程**：发票 → 登记（票号/金额/类型）→ 关联报销单。
- **异常处理**：重复票号校验。
- **优先级**：P2 ｜ **实现基线**：🟡（附件级已支持，台账待建）

#### FR-5.3 借款与还款 ⬜

- **功能描述**：员工借款申请与还款冲销，关联工作流审批。
- **用户故事**：作为财务，我希望管理借款与还款。
- **前置条件**：财务权限、流程定义。
- **操作流程**：借款 → 审批 → 还款冲销。
- **异常处理**：未还清借款限制新借款。
- **优先级**：P2 ｜ **实现基线**：⬜（待评估）

#### FR-5.4 费用统计与预算对比 ✅（部分）

- **功能描述**：按部门/类型统计费用，与预算对比（报表中心 `expense stats` / `dashboard`）。
- **用户故事**：作为负责人，我希望看到费用分布与趋势。
- **前置条件**：`report:view`。
- **操作流程**：报表中心 → 费用统计卡 / 趋势图。
- **异常处理**：无数据时空图。
- **优先级**：P1 ｜ **实现基线**：✅（统计与看板；预算对比二期增强）

### 4.6 模块六：系统管理

#### FR-6.1 用户 / 角色 / 权限管理 ✅

- **功能描述**：用户 CRUD、角色 CRUD、权限点按分类勾选、数据范围、菜单管理。
- **用户故事**：作为管理员，我希望灵活配置角色与权限。
- **前置条件**：`org:role:manage`。
- **操作流程**：系统管理 → 角色 → 勾选权限 → 分配给用户。
- **异常处理**：受保护角色禁止删除。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-6.2 流程配置（审批节点 / 审批人规则）✅

- **功能描述**：工作流定义（节点、审批人规则、条件分支、会签策略）的创建与发布。
- **用户故事**：作为管理员，我希望不写代码即可配置新审批流程。
- **前置条件**：工作流管理权限。
- **操作流程**：工作流 → 定义 → 设计节点/规则 → 发布 → 可发起实例。
- **异常处理**：定义重复编码冲突；未发布不可发起。
- **优先级**：P0 ｜ **实现基线**：✅

#### FR-6.3 操作日志与审计 ✅

- **功能描述**：审计中间件自动记录所有变更类请求与登录/登出，支持模块/动作/状态/时间过滤、趋势图、清理。
- **用户故事**：作为管理员，我希望任何操作都可审计追溯。
- **前置条件**：`audit:view`/`audit:manage`。
- **操作流程**：日志中心 → 过滤 → 查看详情；`audit:manage` 可清理。
- **异常处理**：密码/令牌不落审计。
- **优先级**：P0 ｜ **实现基线**：✅

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| **性能** | 列表接口下推 SQL 分页，不捞全表；工作流趋势分桶在 Python 侧规避方言差异；单页首屏 < 2s（标准环境）。 |
| **安全** | JWT 双令牌（访问 15min、刷新可吊销）；密码 PBKDF2-HMAC 60 万迭代；RBAC 接口级校验；审计不记录敏感凭证；CORS 显式来源、安全头（CSP/X-Frame-Options 等）。 |
| **兼容性** | 现代浏览器（Chrome/Edge/Safari 最新两版）；响应式适配桌面/平板/手机；生产 PostgreSQL，开发 SQLite 双兼容。 |
| **可用性** | 玻璃拟态清晰层级；关键操作二次确认；实时事件（SSE）+ 轮询兜底；优雅停机避免中断在途事务。 |
| **可维护性** | 分层架构（路由/服务/仓储）；配置全环境变量并启动校验；Alembic 可回滚迁移；结构化 JSON 日志 + request_id。 |

## 6. 数据模型（核心实体与关系）

```
User ──< LeaveApplication        (员工 1:N 请假)
User ──< ExpenseClaim             (员工 1:N 报销)
User >─< Department               (员工归属部门，部门含上级自引用)
User >─< Role                      (员工多对多角色)
Role >─< Permission               (角色多对多权限)

WorkflowDefinition 1──< WorkflowInstance   (流程定义 1:N 实例)
WorkflowInstance 1──< WorkflowTask          (实例 1:N 待办任务)
WorkflowInstance 1──< WorkflowNodeLog       (实例 1:N 节点日志)
WorkflowTask >─ User (approver_id / origin_approver_id 留痕)

Attendance 1──< AttendanceSetting (打卡记录 / 班次)
OvertimeRequest ── User            (加班申请)
OfficialDocument 1──< DocumentVersion (公文 1:N 版本)
Announcement 1──< AnnouncementRead  (公告 1:N 阅读回执)
Document (文档中心)                  (分类/版本/鉴权下载)
Notification ── User               (消息中心，user_id 索引+级联)
AuditLog                            (审计日志，查询维度均为物理列)
Signature (电子签单)                 (ref_type/ref_id 关联业务)
```

> 建模引擎（P3）支持零 DDL 动态实体，数据存 JSON 列（灵活但让渡索引，超量需提升物理列）。

## 8. 验收标准

| 模块 | 验收项 | 判据 |
| --- | --- | --- |
| 工作台 | 待办/已办/我发起聚合正确 | 数据与实际实例一致；实时刷新可用 |
| 流程审批 | 请假/报销闭环 | 提交→审批→状态回写全通过；撤回/转办留痕 |
| 流程审批 | 高级动作 | 会签需全员通过；加签/转办/催办均生成节点日志 |
| 人事 | 考勤打卡与统计 | 迟到/早退判定正确；月度统计与 Excel 导出一致 |
| 人事 | 假期扣减 | 请假通过后余额自动减少且不为负 |
| 行政 | 公告回执 | 打开即已读（幂等）；管理员可见阅读明细 |
| 行政 | 文档中心 | 上传/下载/版本历史可用；越权 404 |
| 财务 | 报销打款 | 审批通过→打款→状态正确；重复打款拦截 |
| 系统 | 权限矩阵 | 员工 403 / 管理员 200 边界 16/16 通过 |
| 系统 | 审计 | 变更类请求全部留痕，敏感凭证不记录 |
| 非功能 | 安全 | PBKDF2 60 万迭代；JWT 双令牌；CORS 显式来源 |
| 非功能 | 兼容 | 桌面/平板/手机响应式；PG/SQLite 双跑 |

> **当前验证边界（据 DELIVERY 文档）**：后端 `compileall` 与 `pytest`（标准环境 33+ 项）通过；前端 `tsc --noEmit` 0 错误；**生产构建与运行时冒烟需在标准 Linux/Docker/CI 环境执行**（openharmony 沙箱因原生库限制无法跑 build 与数据库）。
